📋 Relatório de Descobertas — Meta Lead Ads API (v22.0)

🔑 Autenticação — Fluxo Real (Descoberto na Prática)

  • ⚠️ DESCOBERTA CRÍTICA: User Token NÃO acessa /{page_id}/leadgen_forms nem /{form_id}/leads. Retorna erro (#190) This method must be called with a Page Access Token.
  • Solução: User Token → GET /me/accounts?fields=access_token → o JSON de resposta já contém o access_token de cada página no campo data[].access_token. Usar esse token para todas as chamadas de forms e leads.
  • 3 tipos de token: User Token (OAuth login), Page Token (via /me/accounts — expira em ~1h), System User Token (recomendado para produção — nunca expira).
  • Fluxo OAuth: GET https://www.facebook.com/v22.0/dialog/oauth?client_id=...&redirect_uri=...&state=...&scope=... → obtém authorization_code → troca por access_token via GET https://graph.facebook.com/v22.0/oauth/access_token?client_id=...&client_secret=...&code=...
  • System User: Criar em Business Settings → Users → System Users → atribuir à App → gerar token com permissões. Token não expira, ideal server-to-server.
  • App em Development: Só acessa leads de testers/developers/admins do app. Para produção precisa App Review + Go Live.
  • Exemplo real de resposta /me/accounts: 
    {
  "data": [{
    "id": "1054092957791716",
    "name": "Chamalead.ia",
    "category": "Produto/serviço",
    "access_token": "EAApAbVhbqhE...PageTokenAqui...",
    "tasks": ["ADVERTISE","ANALYZE","CREATE_CONTENT","MESSAGING","MODERATE","MANAGE"]
  }]

📡 Endpoints (Testados na Prática)

⚠️ User Token só funciona nos 2 primeiros. Todo o resto exige Page Token.

🔐 Permissões Obrigatórias

  • ads_management — acesso a anúncios
  • ads_read — leitura de dados de anúncios
  • leads_retrieval — essencial para ler leads
  • pages_show_list — listar páginas
  • pages_read_engagement — ler dados de engajamento
  • pages_manage_ads — gerenciar anúncios da página
  • pages_manage_metadata — necessário para webhooks

⚠️ App Review necessário para produção. App em Development só acessa leads de testers.

📦 Campos do Lead (field_data)

Cada lead retorna field_data como array de {name, values[]}. Campos comuns:

  • full_name, first_name, last_name
  • email, phone_number
  • city, state, zip_code
  • custom_disclaimer_responses — checkbox de consentimento
  • + campos customizados definidos no formulário (ex: car_make, selected_dealer)

📊 Rate Limits

Fórmula: 200 × 24 × (número de leads nos últimos 90 dias) por página a cada 24h.

Ex: página com 100 leads/90d → 200 × 24 × 100 = 480,000 chamadas/dia.
Ex: página com 10 leads/90d → 200 × 24 × 10 = 48,000 chamadas/dia.

⚠️ Exceder retorna erro. Implementar exponential backoff.

🔔 Webhooks (Real-Time)

  • Objeto: page, campo: leadgen
  • Payload contém: leadgen_id, page_id, form_id, adgroup_id, ad_id, created_time
  • Recebido o webhook → usar leadgen_id para buscar dados completos via GET /v22.0/{leadgen_id}
  • Pode chegar múltiplos leads em 1 notificação (array de changes[])
  • Meta envia hub.challenge na verificação — responder com mesmo valor
  • Requer HTTPS com TLS 1.2+

🎯 Fluxo Recomendado (Validado na Prática)

  1. Criar Meta App (tipo Business) em developers.facebook.com
  2. Adicionar produtos: Webhooks + Facebook Login na app
  3. Gerar User Token no Graph API Explorer com permissões: ads_management, ads_read, leads_retrieval, pages_show_list, pages_read_engagement, pages_manage_ads, pages_manage_metadata
  4. User Token → Page Token: GET /me/accounts?fields=id,name,access_token → copiar data[].access_token
  5. Usar Page Token para tudo: forms, leads, webhooks
  6. Listar forms: GET /{page_id}/leadgen_forms
  7. Ler leads: GET /{form_id}/leads?fields=id,created_time,field_data (com fallback pra /{page_id}/leads)
  8. Configurar webhook: POST /{page_id}/subscribed_apps?subscribed_fields=leadgen
  9. Pra produção: criar System User no Business Manager (token não expira) + App Review + Go Live
  10. OU: clicar 🚀 AUTOMATIZAR TUDO nessa tool e deixar ela fazer os passos 4-8 sozinha

⚠️ Pegadinhas Comuns (Todas Encontradas na Prática)

  • User Token vs Page Token — erro (#190) This method must be called with a Page Access Token ao usar User Token em leadgen_forms ou /leads. Solução: extrair Page Token via /me/accounts?fields=access_token.
  • Campo "leads" inexistente — erro (#100) Tried accessing nonexisting field (leads) ao chamar /{form_id}/leads em alguns forms. Solução: essa tool tem fallback automático para /{page_id}/leads.
  • App em Development → erro (#3) Apps in dev mode should only access leads submitted from App special roles
  • Lead pode não ter ad_id se for orgânico (is_organic=1)
  • API da Meta pode ser inconsistente — leads podem sumir e reaparecer dias depois
  • Token de página expira em ~1h — usar System User para produção
  • CSV export disponível em /ads/lead_gen/export_csv/ para backup bulk com filtro de data
  • Versão mais recente da API: v22.0 (2025-2026). v25.0 mencionada em docs de features novas.

🔄 Sistema de Fallback (Resiliente)

Esta tool implementa 3 níveis de fallback automático ao buscar leads:

  1. GET /{form_id}/leads — endpoint padrão (funciona na maioria)
  2. GET /{page_id}/leads → filtra por form_id no client — fallback quando #1 retorna erro #100
  3. GET /ads/lead_gen/export_csv/?id={form_id}&type=form — export TSV bruto, último recurso

🧪 Como Testar Leads (App em Development)

  • Usar Lead Ads Testing Tool no Facebook Ads Manager → enviar lead de teste
  • Só testers/developers/admins do app conseguem ver leads em Development mode
  • Form Preview no Ads Manager também gera leads de teste
  • Depois de testar: App Review → Go Live → acesso a leads reais
